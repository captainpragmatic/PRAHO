# Settings whose EFFECT a test asserts: it writes the key, then observes it outside the settings
# app - another app's behaviour, or a rendered page. Reading the value back through SettingsService
# proves storage, which the other checks in lint_settings_coverage.py already cover.
#
# This is a ratchet. `system.maintenance_mode` passed every wiring check while having no
# customer-facing consequence at all, which is why an effect dimension exists. Demanding an effect
# test for all 262 keys at once would only teach people to bypass the gate, so the list records what
# IS tested and the check fails when something leaves it.
#
# What the detector cannot see is assertions. A qualifying file with every assert stripped still
# earns its credit, because the write, the cross-app reach and the request are all still there. So
# this list is a floor on what has been attempted, not a proof of what is covered - reading the test
# is what establishes the assertion discriminates.
#
# Two entries were removed on 2026-09-26 as false credits once the write detection moved from regex
# to AST. `node_deployment.terraform_s3_key_prefix` matched `SettingDef(key="...")` in a catalog
# test, and `notifications.max_async_attachment_kb` matched `if key == "..."` inside a MOCK's
# side_effect - a test that stubs the settings read, the exact opposite of an effect test.
#
# Adding a key here requires the test that earns it. Removing one requires saying why, in the same
# commit.
#
# Recorded 2026-09-26 at 77 of 262 keys.
