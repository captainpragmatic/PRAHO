Primary-source research:
- Ubuntu26.04 is currently GradeA Virtualmin-supported. setquota uses KiB; missing data is not unlimited. Supported ext4 layouts may use native hidden quota inodes or external quota files.
- Webmin2.670 (already pinned in PRAHO's contract lab) supports hidden ext4 inodes and UUID/LABEL detection; old forum failures do not justify converting working native quotas.
- tune2fs v1.47.2 refuses quota-feature changes on mounted/busy filesystems. The issue's quotacheck -cugm recipe must not be repeated on occupied nodes. Fresh root bootstrap is explicitly permitted only before ANY tenant data/services exist, followed by reboot and actual unprivileged write-denial proof.
- Virtualmin8.3 explicit finite creates need quota AND uquota. Linux quota block units are1024; create bandwidth vs modify bw are bytes. apply-quotas can be best-effort: metadata/exit success alone cannot certify the kernel.
- mysql_chgrp/setgid/per-table data on the same quota filesystem matter. Shared system/redo/binlog/temp storage and inode exhaustion are residual node risks, requiring monitoring and native neighbor-isolation tests. Hourly warnings plus10% margin cannot guarantee notice before burst exhaustion.
- PRAHO bandwidth is independently collected Apache HTTP(S) response-body bytes with owner/canonical-node/operator-month evidence; it does NOT depend on Virtualmin bw.pl totals.

## 6. Implementation clarifications from review

- Capacity admission means fresh native filesystem available bytes minus unresolved positive-delta reservations and the configured node free-space reserve. It is admission control, not a promise that every sold cap can fill simultaneously. Reserve only in Account → sorted Servers → Service native workers, never a financial transaction. Release once on verified application or proven non-dispatch/fenced terminal cancellation, supersession or failure; elapsed leases alone never release uncertainty. Every reservation is keyed to its application identity.
- Qualification checks MariaDB effective capabilities and its systemd bounding set, plus every existing tenant table's actual single tablespace/datafile. Enabling innodb_file_per_table does not relocate historical shared data. Native application updates quota/uquota metadata and both kernel caps; a normal later lifecycle action must preserve them.
- Native metadata mutation runs in a fixed synchronous helper inheriting the account flock. Kernel updates are direct synchronous quotactl calls in the coordinator. No mutating Virtualmin/setquota command descendants can outlive the lock. Partial results stay uncertain until fenced. Test SIGKILL of a coordinator with an issued real child.
- Ownership transfer advances the allowance revision without resolving edited catalog defaults. Recheck caller owner identity after acquiring Service, including A → B → A invalidating old revisions. Use NO KEY UPDATE on financial Service/Subscription locks where keys are unchanged; keep the stronger ownership fence where it excludes new native references.
- Downgrade fit is against purchased A (or A plus an explicitly valid fixed raise), rather than hidden headroom. Cancellation ends once its target renewal is committed to preparation. Later overuse retains the accepted lower billing terms and data under the approved attention policy, with an urgent overdue staff escalation; it does not authorize an automatic below-usage downgrade. Explicit raise expiry remains a separately preauthorized cap reduction.
- Preserve upgrades over issued unpaid frozen renewals. Distinguish the original fixed payable base obligation from settled supplement coverage; bind both to immutable interval/document evidence. If that base is later voided or refunded, invalidate affected coverage for review. Old renewal settlement must never restore the previous recurring price.
- Quote proration starts at the frozen quote instant. The bound on-session attempt uses a hard application-authority deadline before the current interval ends; after that deadline late funds go to paid review and cannot apply stale terms. Recovery keeps the same provider attempt. A provider outage cannot indefinitely freeze unrelated normal renewals: revoke stale plan-application authority and retain recovery/review ownership.
- One Platform owner handles each customer notification phase. Reuse the document mail pipeline for proforma issuance and the settled invoice/payment-applying phase, with plan-change context, rather than send duplicate new phase mail. Completion/attention remain separate idempotent operational events. Native import alone never disables its warnings: explicit handover reconciles existing settings before Platform starts notices.
